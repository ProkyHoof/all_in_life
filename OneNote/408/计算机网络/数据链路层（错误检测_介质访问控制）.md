# 错误检测

数据在传输过程中，由于各种因素（如干扰、噪声、信号衰减），可能导致比特错误（比特翻转）。数据链路层提供错误检测机制，保证数据传输的可靠性，使得接收端能检测出数据的错误并采取相应措施（如请求重传）。
 
# 错误检测-常见的检测方法

奇偶校验（Parity Check）  
检验和（Checksum）  
循环冗余校验（CRC）
 
# 错误检测-奇偶校验（Parity Check）

奇校验还是偶校验是发送方与接收方事先协商好的。  
不论是奇校验还是偶校验，判断依据都是数据中1的个数的奇偶性。  
数据的1的个数 + 校验位 = 满足奇校验或偶校验的要求。  
优点：实现简单、开销小。  
缺点：检测能力弱、只能检测奇数个比特的错误，偶数个比特错误无法检测。
 
# 错误检测-校验和（Checksum）

校验和是一种常用的错误检测方法，广泛用于TCP/IP协议中，具体操作方法如下：

1. 发送方将待发送的数据分成若干段（通常16位为一组）。
2. 将这些数据段进行二进制求和。
3. 若求和过程中产生进位，则将进位部分回卷相加（循环进位）。
4. 最后将求和结果取反，作为校验和附加在数据后发送。
5. 接收方验证后如果结果全部是1说明数无误，否则数据有问题。

优点：比奇偶校验强，能检测更多错误，简单高效，计算量少。  
缺点：不能检测所有错误（例如数据中部分比特位置翻转后总和仍相同，无法发现）
 
# 错误检测-循环冗余校验（Cyclic Redundancy Check）

CRC是一种广泛用于数据链路层的错误检测方法，常用于以太网、HDLC、PPP等协议。

1. 发送方和接收方事先约定一个叫作生成多项式的二进制序列。
2. 生成多项式如果有n位，发送方在发送数据末尾添加n-1个0。
3. 发送方使用末尾添加0的数据除以生成多项式，得到的余数为CRC码。
4. 发送方发送原始数据 + CRC。
5. 接收端收到数据后，用同样的生成多项式去除。如果余数为0，则数据无误；否则数据有误。
 
# 为什么1101叫做“生成多项式”？

CRC中的多项式实际上是“二进制多项式”。

1. 多项式的系数只能是0或1，而不可能是其他数字。
2. 系数为1的项表示存在该项，系数为0表示不存在该项。
 
# 生成多项式是如何确定的？

生成多项式不是随机的，也不是根据数据临时决定的，是事先由协议规定好的，固定不变的。

1. 每一种协议在制定之初就明确规定了使用的CRC生成多项式。
2. 不同协议使用的生成多项式不同，且标准化。
3. 发送端和接收端都按照协议规定使用的固定生成多项式进行计算。

# 介质访问控制子层（MAC）

介质访问控制子层（Medium Access Control，MAC）：属于数据链路层的一个子层，主要负责在共享介质上协调多个节点的传输，确保各节点按照一定规则访问信道。

# 网络链路

点对点链路：有链路一端的单个发送方和链路另外一端的单一端的单个接收方组成。  
广播链路：多个发送方和接收方都连接到相同的、单一的、共享的广播信道上。
 
# 广播

当任何一个节点传输一帧数据时，其它节点都会收到一个副本。
 
# ALOHA协议

诞生背景：1970年代，夏威夷大学用于远程岛屿之间的无线数据传输。  
核心问题：多个设备共享同一个信道，如何协调谁来发送数据？  
发送机制：

1. 节点一旦有数据就立刻发送，无需监听信道状态。
2. 不关心其它节点是否在发送，属于“盲发”。

冲突处理：

1. 节点会等待一段时间（随机退避）后再次尝试发送。

理论最大信道利用率：

1. 不有约18.4%。
 
# 时隙ALOHA

1. 将时间划分“时隙”，节点只能在时隙开始时发数据。
2. 冲突只能发生在同一个时隙内，不再有“部分重叠”，冲突概率降低。
3. 理论最大信道利用率36.8%。
4. 要求各节点系统时间同步，增加了实现复杂度。

# 1-坚持型载波监听多路访问（1-persistent CSM）

节点会不断监听信道，一旦发现空闲，立即抢占发送。  
信道忙就继续监听，直到空闲就马上发，不等待、不犹豫、不随机。
 
# 非坚持型载波监听多路访问（Non-persistent CSM）

发送数据前监听信道，如果信道空闲，立刻发送。  
信道忙则不会持续监听信道，随机等待一段时间后再重复上面的操作。
 
# p-坚持型载波监听多路访问（p-persistent CSM）

在监听到信道空闲时，不一定马上发，而是以“概率p”发送，以“概率1-p”等待下一时隙。  
它是一个折中的策略：  
不像1-坚持那样激进（信道一空就一定发）  
也不像非坚持那样“转头就走”（回头不知道什么时候回来）  
“我有点礼貌，但也不太佛系”
 
p值如何确定？  
如果p = 1 就变成了1-坚持CSMA。  
如果p很小（接近0） 发言概率低，等很久，系统利用率低。  
通常根据网络负载动态调整p是最优策略（但比较复杂）
 
# CSMA/CD（CSMA with Collision Detection）

边发边听，发现冲突马上停止，并等待随机时间再试一次。  
节点不仅发送前监听，还在发送的同时持续监听，一旦听到有别的节点的数据与自己数据冲突，立即停下来。  
边发边听，冲突即听，随机等待后重试。是以太网进经典共享介质环境下的核心协议。
 
# 传播延迟

传播延迟就是数据或信号从发送节点传到接收节点的时间。
 
# 最大传播延迟

最远两个节点之间信号传播的时间，这就是最大传播延迟。  
它决定了，最坏情况下，发送节点多久才能得知是否发生冲突。
 
# 争用期（往返传播延迟）

发送节点多久才能得知是否发生冲突。  
最大传播延迟为T，则争用期为2T。
 
# 最小帧长

最小帧长的目的，是保证数据帧发送所用的最短时间\>=往返传播延迟  
如果数据帧过小，那么碰撞发生之间监听就停止了，那么就无法检测冲突。  
最小帧长 = 争用期（2T） * 传输速率
 
# 退避时间

当多个节点同时发现冲突，同时停下后，如果都同时重新发送，一定再冲突所以设计了随机等待机制（退避），避免持续碰撞
