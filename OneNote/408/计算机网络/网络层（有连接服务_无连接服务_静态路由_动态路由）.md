# 网络层（第三层）

将数据传输到目的地址。  
目的地址可以是多个网络通过路由器连接而成的某个地址。  
该层负责寻址和路由选择。
 
# 网络层数据传输方式——无连接服务

定义：每个数据包（数据报）都是独立的，彼此之间没有任何关联。每个数据包携带了足够的信息，以便能够独立地从原地址传输到目的地址。没有事先建立连接，也不需要维护连接状态。在这样的环境中，数据包通常被称为数据报，这种网络通常被称为数据报网络。
 
特点：  
无需建立连接：发送方和接收方之间不需要建立连接，数据包可以直接发送。  
每个数据独立：每个数据包都有完整的目的地址和路由信息，发送和接收的数据包之间没有任何关联。  
不保证可靠性：由于每个数据包是独立的，网络层不保证数据包的可靠传输，数据报可能丢失、乱序或者重复。  
适用场景：适用于那些对实时性要求高且可以容忍丢包的应用，如视频会议、实时游戏等。
 
# 网络层数据传输方式——有连接服务

定义：发送方和接收方在数据传输之前需要通过网络建立一条虚拟的通信路径（虚电路），所有数据包通过这条虚电路进行传输。虚电路在通信过程中始终存在，直到通信结束。这种网络称为虚电路网络。
 
特点：  
建立连接：发送方和接收方在数据传输前必须进行连接建立，通过建立虚拟电路来保证数据能够按照特定的顺序到达接收方。  
可靠传输：在虚电路网络中，数据包的顺序和完整性都能得到保证，网络层会对数据报进行确认和重传。  
固定路径：所有的数据包都会沿着同一路径传输，这样便于提供高效的流量控制和错误检测。  
适用场景：适用于对可靠性要求高、数据顺序需要保证的应用，如文件传输、电子邮件等。

# 路由与转发

路由（Routing）：指的是在网络层（主要是IP层）选择数据包从源到目的地的最佳路径的过程。路由涉及到路由表的维护和更新，通常由路由协议动态计算。  
转发（Forwarding）：是指在路由选择已经完成之后，设备（如路由器）将数据包从一个接口转发到另一个接口的过程。转发的速度要求非常高，因为它直接影响到数据包的传输效率。
 
# 跳帧算法（Hop-by-Hop Routing）

跳帧算法是数据包从源节点传送到目的节点过程中，每一跳由各个路由器独立决定下一跳路由器的转发行为。这种转发行为基于路由表中的信息，每个路由器仅根据目标地址和自己的路由表做出转发决策。它并不需要局部网络信息，只需要局部的信息。
 
# 路由算法

# 静态路由

定义：静态路由是由网络管理员手动配置的固定路由。路由器的路由表不会根据网络状态变化而自动调整，需要手动修改配置。
 
优点：配置容易，适用于小型、简单网络。  
控制性强：管理员可以精确控制数据包的路由路径。  
缺点  
不灵活：如果网络拓补发生变化，必须手动重新配置。  
扩展性差：随着网络规模扩大，静态路由配置变得难以维护。  
对网络故障的应对能力差：如果某条路由失效，管理员必须手动修改路由表。
 
# 动态路由

定义：动态路由是通过路由协议自动计算并更新路由表的方式。路由器通过与其他路由器交换信息来学习和选择最佳路径，动态调整路由。  
优点  
自动化：动态路由协议能够根据网络拓补变化自动调整路由，减少人工干预。  
适应性强：适合中大型网络，能够根据网络状态变化动态调整路由。  
故障恢复能力强：当某条路径发生故障时，路由协议能够快速计算出新的路径。  
缺点  
配置复杂：需要配置和管理路由协议，可能涉及较复杂的路由策略。  
网络负载：动态路由协议会定期交换路由信息，这可能增加网络负载。  
可能会发生路由环路等问题，需要谨慎配置。

# 距离向量路由算法

每个路由器（节点）维护一个路由表，路由表中有到达其他路由器的最短路径及到达那里使用的链路。通过定期与邻居交换路由表信息，更新自己的路由信息，最终每台路由器都了解到达目的地的最佳链路。
 
# 距离向量路由算法-工作过程

初始化：每个路由器只知道直连网络的距离为1，其他都为“不可达”。  
周期性广播：定期将自己的路由表发送给所有邻居。  
路由表更新：接收到邻居的路由信息后，更新自己的路由表。  
收敛：经过若干轮交换，最终每个路由器都知道达到所有目标的最短路径。

# 链路状态路由算法

每个路由器用过“广播”自己与邻居的链路状态（如带宽、延迟）给全网。  
所有路由器最终都构建出相同的网络拓补图。  
每个路由器用Dijkstra算法计算出到各节点的最短路径 —— 路由表。
 
# 链路状态路由算法-工作流程

1. 邻居发现。
2. 测量链路状态（延迟、带宽）。
3. 生成链路状态数据包。
4. 泛洪（flooding）数据包给全网。
5. 本地运行Dijkstra算法构建最短路径树，生成路由表。

# 邻居发现

当一台路由器启动时，第一个任务就是找出谁是它的邻居。
 
# 测量链路状态（设置链路成本）

路由器到达邻居的成本可以自动设置，也可以由网络运营商配置。

1. 成本与链路带宽成反比，高容量宽带的路径成为路由更好的选择。

|   |   |
|---|---|
|以太网1Gb/s|成本度量1|
|以太网100Mb/s|成本度量10|

3. 如果网络在地理位置上分散，则链路的延迟可以作为成本的组成部分。
 
# 生成链路状态数据包

一旦手机到交换需要的信息，每台路由器下一步的工作就是构建一个包含所有这些数据的包。  
数据包：发送方标识符、序号、年龄（age）、邻居列表和成本。
 
# 泛洪（flooding）数据包给全网

将每一个进来的数据包发送给除了该数据包到达的那个线路以外的每一条输出线路上。
 
使用泛洪法将链路状态数据包发送给所有路由器。  
为了保持泛洪可控，每个数据包都包含一个序号，序号随着每一个新数据包发出而递增。

1. 如果是一个新数据包，使用泛洪进行转发。
2. 如果是一个重复的数据包，则将它丢弃。
3. 如果数据包的序号小于当前已观察到的最大序号，则将该数据当作过时数据包拒绝接受。
 
# 抑制泛洪

让路由器跟踪已经泛洪过的数据包，从而避免第二次发送。可以让源路由器在接收到来自主机的每一个数据包中放置一个序号，通过记录序号避免再泛洪出去。
 
# 计算路径生成路由表

当一台路由器收到了全部的链路状态数据包之后，就可以构造完整的网络图，路由器本地运行Dijkstra算法，从而构造出从本地发到所有可能目标的最短路径。

1. 算法的结构信息存放路由表中，根据这个信息，路由器就可以知道数据包使用哪条链路可以尽快到达目的地。
2. 与距离向量路由算法相比，链路状态路由算法需要更多的内存和计算量，对于大型网络而言，仍然是一个问题。不过链路状态不再受慢收敛问题的影响。
