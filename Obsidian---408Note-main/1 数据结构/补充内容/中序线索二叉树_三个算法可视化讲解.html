在同一棵树上观察 Firstnode、Nextnode 与 Inorder。 实线代表真实孩子，橙色虚线代表前驱/后继线索。点击“下一步”观察指针如何移动。
真实孩子边 线索边 当前结点 已访问结点

Firstnode：不断沿真实左孩子下降

准备：从 A 开始。检查 A 的 ltag；只要 ltag=0，就沿真正的左孩子继续向下。

当前算法代码

ThreadNode *Firstnode(ThreadNode *p){ while(p->ltag == 0) p = p->lChild; return p; }
ThreadNode *Nextnode(ThreadNode *p){ if(p->rtag == 0) return Firstnode(p->rChild); else return p->rChild; }
void Inorder(ThreadNode *T){ for(ThreadNode *p = Firstnode(T); p != NULL; p = Nextnode(p)) visit(p); }
Firstnode 的核心：
只沿着 ltag = 0 的真实左孩子边走。

为什么不能判断 lChild != NULL？

线索化以后，lChild 即使非空，也可能指向“前驱线索”。必须查看 ltag，才能区分真实孩子与线索。

停止条件

遇到 ltag=1，说明当前结点没有真实左孩子。它就是该子树中第一个被中序访问的结点。

rtag = 0
有真实右子树
检查 p
rtag = 1
右指针是线索

有右子树

进入右子树后，不能直接返回右孩子；还要继续找该右子树的最左结点。

没有右子树

rChild 已被改造成中序后继线索，可以直接返回。若为 NULL，说明 p 是中序序列最后一个结点。

整体思路：
先找起点，再不断执行 p = Nextnode(p)。

它像遍历数组

数组用 i++ 找下一个元素；线索二叉树用 Nextnode(p) 找下一个中序结点。

为什么不需要递归栈？

原本由递归栈保存的“返回到哪个祖先”信息，部分被存入空指针形成的线索中。
