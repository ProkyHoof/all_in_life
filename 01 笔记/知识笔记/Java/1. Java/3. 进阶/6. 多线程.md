# 多线程
## 多线程
### 线程
线程是操作系统能够进行运算调度的最小单位。它被包含在**进程**之中，是进程中的实际运作单位。  
**简单理解：**引用软件中互相独立，可以同时运行的功能。  
### 进程
进程是程序的基本执行实体。  
### 多线程的引用场景
软件中的耗时操作。拷贝、迁移大文件。加载大量的资源文件。  
所有的聊天软件。所有的后台服务器。  
## 并发并行
### 并发和并行
**并发：**在同一时刻，有多个指令在单个CPU上**交替**执行。  
**并行：**在同一时刻，有多个指令在多个CPU上同时执行。  
## 多线程的实现方式
1. 继承Thread类的方式进行实现。  
2. 实现Runnable接口的方式进行实现。  
3. 利用Callable接口和Future接口方式实现。  
**多线程第一种启动方式**  

**多线程第三种启动方式**  
```java
public static void main(String[] args) {
MyCallable mc = new MyCallable();
```

### 同步代码块
把操作共享数据的代码锁起来。  
![](../../../../../03%20附件/attachments/知识附件/Java/1.%20Java/进阶/多线程%20image%20fe11373918e872e3.png)  
**特点****1****：**锁默认打开，有一个线程进去了，锁自动关闭。  
**特点****2****：**里面的代码全部执行完毕，线程出来，锁自动打开。  
```java
public class MyThread extends Thread {

while (true) {

}
ticket++;
System.out.println(getName() + "正在售卖" + ticket + "张票");

break;
}
}
}
}
}
```

### Lock锁
虽然我们可以理解同步代码块和同步方法的锁对象问题，但是我们并没有直接看到在哪里加上锁，在哪里释放了锁，为了更清晰的表达如何加锁和释放锁，JDK5以后提供了一个新的锁对象Lock。  
Lock实现提供比使用synchronized方法和语句可以获得更广泛的锁定操作。  
Lock中提供了获得锁和释放锁的方法。  
void lock(); 获得锁  
void unlock(); 释放锁  
Lock是接口不能直接实例化，这里采用它的实现类ReentrantLock来实例化。  
ReentrantLock的构造方法。  
ReentrantLock(); 创建一个ReentrantLock的实例。  
```java
public class MyRunnable implements Runnable {
static int stiket;
static Lock lock = new ReentrantLock();
@Override
public void run() {
while (true) {
lock.lock();
try {
if (ticket == 100) {
break;
} else {
Thread.sleep(10);
ticket++;
System.out.println(Thread.currentThread().getName() + "在卖第" + ticket + "张票");
}
} catch (InterruptedException e) {
e.printStackTrace();
} finally {
lock.unlock();
}
}
}
}
```

## 线程池
### 线程池主要核心原理
1. 创建一个池子，池子中是空的。  
2. 提交任务时，池子会创建新的线程对象，任务执行完毕，线程归还给池子。下回再提交任务时，不需要创建新的线程，直接服用已有的线程即可。  
3. 但是如果提交任务时，池子中没有空闲线程，也无法创建新的线程，任务就会排队等待。  
### 线程池代码实现
1. 创建线程池。  
Executors：线程池的工具类通过调用方法返回不同类型的线程池对象。  
![](../../../../../03%20附件/attachments/知识附件/Java/1.%20Java/进阶/多线程%20image%20384af7728b1f3d33.png)4. 提交任务。  
5. 所有的任务全部执行完毕，关闭线程池。  
```java
public static void main(String[] args) {
ExecutorService pooll = Executors.newCachedThreadPool();
pooll.submit(new MyRunable());
```

**不断的提交任务，会有以下三个临界点：**  
1. 当核心线程满时，再提交任务就会排队。  
2. 当核心线程满，队伍满时，会创建临时线程。  
3. 当核心线程满，队伍满，临时线程满时，会触发任务拒绝策略。
